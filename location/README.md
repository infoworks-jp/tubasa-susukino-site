# すすきの3Dロケハン

参考ツールの正規GLB書き出しを利用した400m四方の詳細街区と、写真に基づく横丁入口を、Three.jsの独自ビューアで静的配信する。本体コードのコピー・iframe埋め込みは行わない。

- 参考ツールのモデル出力は商用利用・配布可能。[利用根拠・制作手順](reference-model.md)を参照。地図部分はODbL、出典を画面・PNG・GLBに保持する。
- モデルは近景約11MB＋遠景用樹木約1.4MB。共有頂点、Meshopt圧縮、樹木650本のGPUインスタンス化を使用し、近景の形状は間引かず、遠くの樹木だけ専用の簡略形状に切り替える。初回読み込みは転送量を表示する。
- 奥行きと面の向きを別パスで描画し、境界から輪郭と折れ目を抽出する。カラー・線画・線画＋トーン・夜景、9つのカメラ、タッチ・キーボード操作を維持する。
- 建物の実形状に対するBVHレイキャストでカメラの最低高さを決める。未知の高さは参考モデルの推定であり、現実の衝突保証ではない。
- 入口写真はユーザーが制作利用可能と確認済み。看板の文字を代用フォントで作らず、四隅を測定した写真面と輪郭抽出で表現する。[位置の根拠](position-evidence.md)とphoto-facade.mjsを参照。絶対寸法・屋内区画は未実測。
- 写真未収録区画の窓、店先、看板、屋上設備は参考モデルの生成装飾。これらの区画は実景をトレースした外観ではない。標高異常のあったモデルは採用せず平坦なモデルを使用する。
- PNGは横2400px、下部180pxに出典。GLBは形状、写真のテクスチャ、出典・地点情報を含む。画面の漫画処理はGLBへ焼き込まない。
- 閲覧時は同一サイトの静的ファイルのみ。AI、Ollama、有料地図APIを呼び出さない。公式トップや既存メニューなどは改変しない。

## ビルド・検証

```sh
npm run build:location
npm run test
node tests/deploy-contract-qa.mjs
# ローカルサーバー8080を起動した上で
node tests/location-browser-qa.mjs
```

city.bundle.jsを直接編集せず、city.source.mjs・manga-renderer.mjs・photo-facade.mjsを編集して再生成する。公開経路は既存pages.yml。3D専用QAと既存サイトの全公開ゲートを維持する。

CIはSwiftShaderによるCPU描画で同じ画面と検証を実行する。詳細モデルのGPU処理完了を待つため、操作・撮影待ち90秒、ジョブ上限30分を確保する。画像・操作・出典・保存・衝突の合否条件は維持する。Macの実GPU検証はLOCATION_QA_HARDWARE=1で同じテストを実行できる。

## 写真から描き起こした漫画街区（2026-10-14）

`assets/manga/` の静的原画を `artwork.mjs` / `photo-facade.mjs` / `illustrated-street.mjs` から読み込みます。壁・主看板・突出看板・庇・入口を分けた浅い立体表現です。原画内の未確認文字を含む部分はUV範囲から除外。全景の写真を画面に貼り付ける方式ではありません。

`MangaRenderer` の法線パスのαを原画マスクに使い、細線と網点に二度目の二値化がかからないようにしています。案内ラベルは後段で合成して可読性を保持します。GLBでは通常のテクスチャ付きメッシュとして原画も保存します。

北側の対象建物は既存の生成外観を置換し、同じ衝突用メッシュに新しい建物形状を結合してBVHを再構築します。地図ベースの形状を保ちつつ、窓や屋根が原画を貫通することを防ぎます。対象街区に自動配置された装飾樹木を除外し、看板を見通せるようにしました。

「向かいの街並み」で北側を表示できます。入口カメラはPCで原画を大きく、スマホでは入口を中央に表示します。現在の初期表示は「横丁までの街並み」です。PNGは幅2400px＋出典欄180px、GLBとページにも写真の出典を保持します。

原画・写真の出典、ライセンス、表現範囲は [artwork-sources.md](artwork-sources.md) を参照。訪問者のAI/API利用はありません。

配信には原画PNGと全画素一致を検証した可逆WebP（3枚計6.3MB）を使用。漫画原画はカラー・夜景でも描き起こしの線を保持します。全景の網点処理と原画内の描画済み網点は別に扱います。

交差点のカメラは街から看板を見上げられる目線に調整。回転角の下限側制限を緩める一方、建物・地面との接触防止は維持します。つばさの案内ラベルは右上の拡大縮小ボタンの領域を避けます。

## PLATEAUによる実物由来の外観（2026-10-14追加）

交差点の北側を中心に85棟を、札幌市PLATEAUの写真付きLOD2モデルへ置換。窓や看板は元写真の配置を利用し、漫画モードで境界抽出と網点処理を行う。当初は既存の漫画原画を持つランドマークを維持。交差点北側は下記の写真投影へ更新。重複する概略建物の壁・窓を実物モデルの外周で除外し、追加した4メッシュも衝突判定へ登録する。

2枚の8192角テクスチャを、使用画素の解像度を変えず2048×4096の2枚へ詰め直した（展開時の画素数を1/8に削減）。GLB約7.1MBを追加。画面、PNG、GLBに2020年度の資料であることと出典を保持する。詳しい範囲・条件・再生成手順は[plateau-sources.md](plateau-sources.md)。

全街区の実写トレースは未完。写真の解像度差と未収録区画があり、屋内の通路・店の並びは写真・動画による確認を待つ。生成した店名や架空の店舗区画で補完しない。

## 看板と低層階の実写に基づく描き込み（2026-10-14更新）

交差点北側の旧生成原画4面を、実際の写真から計28面を測定した外壁・看板へ置換。`facade-projection.mjs` に写真の四隅・元写真寸法・切り出し領域・建物の端点を記録し、`surveyed-facades.mjs` で各面に射影補正したUVを設定する。手前の時計に隠れた範囲は別写真で補完し、時計を壁に貼り込まない。

初期表示は「向かいの街並み」。既存6種類に「看板の細部を見る」を追加し、街路の視点では遠方のつばさラベルを画面端へ強制表示しない。写真の文字・窓割りを保持して線画化し、従来の粗いPLATEAU写真とは別の細かな網点を使用する。既存の横丁入口・ニッカの原画は維持。

2つの写真アトラスは可逆WebPで計約6.3MB。旧北側原画は読み込まない。PNGは幅2400px＋出典欄180px。GLBは通常のUV・画像・写真の測定点・4人の写真作者と利用条件を保持する。画面の漫画処理はPNGで保存する。

`node tests/facade-projection-qa.mjs` で測定した四隅、射影変換、UVの範囲・反転、配信画像を確認。3DブラウザQAは初期表示、全モード、全カメラ、ラベルの有無、保存された28面の資料情報も検査する。詳しい出典と未再現範囲は [artwork-sources.md](artwork-sources.md)。

### 2026-10-14: 交差点から新ラーメン横丁への連続街並み

`route-facades.mjs` に3棟の地図輪郭・30面の写真投影・共有入口基準を追加。`surveyed-facades.mjs` の射影変換を北側28面と南側30面で共用。`refineLandmarkMasses` はこの3棟の元の壁と装飾窓も置換し、衝突判定用の実ジオメトリへ含めます。入口の位置は `entranceAnchor` から経緯度へ変換し、看板・開口部・案内図で共有します。

初期カメラは「横丁までの街並み」。PCとスマホの構図を分け、既存7視点も保持。提供写真で見える入口の文字を直接使い、資料のない通路や他店の並びは追加していません。2018年・2022年・提供写真の時点を混同しないようページとGLBに出典を保存。

`node tests/facade-projection-qa.mjs` は58面のUV・射影・素材、親建物との接合に加え、実際の圧縮GLBを再構築して仮窓が前面に残っていないことをレイで検査します。ブラウザ検査は初期街並み、8視点、4モード、写真を含む保存、既存の北側の空の網点回帰を検査します。


### 2026-10-14: 窓・外壁の立体化と入口看板の差し色

`route-relief.mjs` に写真上の窓割り・開口位置を記録し、`facade-relief.mjs` で写真面を分割。11面に45の窓・扉のくぼみと外壁の段差を作り、写真のUVを保ったまま枠と奥の面を分離する。奥行きは15〜42cm程度の概略で、現地実測ではない。地図の建物本体を突き抜けないことをレイキャストで検証する。

`route-architecture.mjs` は横丁上部の手すり・庇、3棟の笠木・柱、第2グリーンビル1階の見える柱とガラス面を追加。人・車に隠れるガラス面は無地とし、店舗内や店名を補完しない。歩道は既存の地図モデルの歩道メッシュを97地点で測定し、建物の足元から縁石まで連続した面を作る。舗装目地・点字ブロックの幅と位置は写真を基にした概略で、測量図やバリアフリー経路ではない。

「窓と歩道を見る」で立体を斜めから確認できる。線画・線画＋トーンでは実写真の主看板1面だけ、緑・赤・クリームの差し色を残す。元写真65%と整理した色35%を混ぜ、文字と模様を保持。カラー・夜景の色は従来通り。PNGには差し色、GLBには窓のくぼみ・手すり・舗装・元写真と出典が保存される。画面の漫画処理と差し色シェーダーはGLBへ焼き込まない。

### 2026-10-14: 第3グリーンビルの看板ずれ・入口案内

第3グリーンビルの4段の写真面を1面へ統合（南側は27面、北側と計55面）。独立した縦横比・奥行きで同じ縦看板を切断していた原因を除去。写真全体を共通の射影変換で配置し、BIG ECHO・PROMISE・縦看板のケースは写真上の四隅で切り抜いて浅く立体化する。背景には同じ形の穴を開けるので、斜め視点でも下の画像が二重にならない。576点のレイで面の欠落・重複を検査。既存45か所の窓・扉の凹み、歩道と差し色は維持。

3Dの案内ラベルを「つばさへの入口」に変更し、案内線の先端を実際に描画した新ラーメン横丁の看板中心に固定。「つばさへの入口」は道路側から入口を見渡す視点、「横丁看板を近くで」は近接視点。店舗の座標・地下1階・通路の一番奥という情報は別に保持する。GLBにも入口案内と店舗情報を別々に記録。写真時点や寸法の概略という制限は変わらない。


## 2025年資料によるグリーンビルの広告更新

第2・第3グリーンビルの2018年の広告写真を、現在の店名・配色・並びを表す独自イラストへ置換。Google Mapsの画素を再利用せず、SVGを node scripts/build-green-signs.mjs で生成し、node scripts/render-green-signs.mjs でWebP化。後者はPlaywrightをインストールした検証環境で、8080番のローカルサーバーを起動して実行する。日本語フォントはmacOSのヒラギノを使用。形状と窓の凹み、横丁の主看板の写真・差し色、共通の親建物との位置合わせは維持。広告の文字・図柄はイラスト表現であり、写真の精密なトレースではない。

重複した入口上の広告4面を除去し、南側23面、北側28面の計51面。第3ビルは13枚の広告ケースを共通の原画座標に登録。屋上広告の上端33mと下段の帯を入口写真に合わせた概略比率へ修正。旧2018年アトラスは描画・出力に読み込まない。GLBの illustration / illustrationDate と写真の photoDate を区別する。

射影のない矩形UVでは再分割を省略し、写真の射影UVだけ5段階の再分割を維持。同じ描画を保ちながら、新しい13枚の看板ケースによる頂点数の増加を避ける。576本のレイによる壁面の連続性と、新旧看板の重複防止を回帰検査する。

## 読み込みの段階化（2026-10）

交差点〜横丁入口の街区・看板・歩道を先に表示し、回転・拡大・カメラ切替を開始する。
85棟のPLATEAUは写真を分離した正確な形状を先に読み込み、衝突判定も完成時と同じにする。
北側の高解像度外壁とPLATEAUの写真は初回描画後に並行取得して載せる。全体の写真解像度・最終形状・漫画シェーダーは維持する。
距離による個別建物のダウンロード分割は行っていない。周辺は自動で最後まで読み込む。

- `data-city-interactive="true"`：主要街並みを操作可能。User Timing `city-interactive`。
- `data-city-ready="true"`：全モデル・外壁を統合済み。`city-complete`。
- PNG / GLB保存は全体の完了後に有効化し、不完全なモデルの保存を防ぐ。
- 周辺の通信失敗時も主要街並みは操作可能。再読み込みボタンを表示し、保存は無効のまま。
- 読み込み完了によってカメラや表示モードをリセットしない。

PLATEAUの分割は `node scripts/split-plateau-loading.mjs`。元GLBから形状とWebPのバイトを
そのまま分離し、再圧縮・形状削減はしない。`tests/plateau-data-qa.mjs` が元の全属性・変換・
写真・出典との一致を検査する。通常表示では元の写真一体GLBを重複取得しない。

歩道97地点の既存サンプリングは `scripts/build-route-pavement.mjs` で制作時に実行し、
`location/pavement.generated.mjs` に保存する。地図・街区境界を変更したら再生成する。
`node tests/facade-projection-qa.mjs` が元の地図メッシュを毎回再計算して完全一致を検証する。
`tests/location-loading-qa.mjs` は周辺通信を意図的に止め、先行操作・保存待ち・視点維持・失敗復旧を検証する。
