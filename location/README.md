# 味一番つばさ 3Dロケハン

参考ツール「どこでもロケハン」の実地図→3D街区・線画/トーン・書き出しという体験を、つばさ周辺専用ページとして独自実装。
参考ツールのコード・画像は複製せず、Three.js (MIT) とOpenStreetMap由来のOpenFreeMap/OpenMapTilesデータを使用。
元ツールは `frame-ancestors` により他ドメインへの埋め込み不可。

- 実際の建物の平面形状と地図タイルの高さを使用。高さ欠落時は15m。
- 約420m四方の街区、317棟分の平面形状。地図データは2026-10-13取得。
- カラー・輪郭線・網点トーン・夜景、回転/拡大/移動、3つのカメラ位置。スマホの俯瞰は距離1050m、PCは650m。従来の530mでは街区端が大きく見切れたため、画面比率で距離を変える。
- 窓は四角い輪郭による装飾。建物の看板や入口、地形の標高は再現しない。
- PNGは幅2400px（縦は画面比率を維持）で書き出し、110pxの下部欄に24px以上の文字で出典を焼き込む。GLBのextrasに出典・地図メタデータ・単位・軸・未再現部分を保持。網点は画面用シェーダーのためGLBへは焼き込まない。
- 利用時のAI API呼び出し無し。地図・ライブラリは同一サイトから静的配信。
- 他の場所の検索、広さ変更、4km遠景、KML取り込み、地形再現は今回のページには含まれない。
- メニュー、TOPのFluid Text、既存の夜のすすきの案内は維持する。

## 再ビルド

リポジトリの既存依存 (three 0.183.2 / esbuild 0.25.9) を使用。

```bash
npx esbuild location/city.source.mjs --bundle --format=esm --minify --outfile=location/city.bundle.js
```

## 検証

`tests/location-browser-qa.mjs` と `.github/workflows/location-qa.yml`:
参考ツールの無改造表示を確認し、PC・スマートフォン幅で4モード、カメラ、キーボード操作、PNG/GLB保存、横スクロール、例外/シェーダーエラーを確認。
証拠はActionsの location-scout アーティファクトに保存。
既存の公開には `.github/workflows/pages.yml` の検証・配信経路を使う。

## 改修で確認・修正した問題

- PC・390pxの実画面で近景のつばさラベルが上端で欠けた。ラベルを画面内の余白へ収め、表示サイズを一定に保つ。
- 北が上の位置関係図を取得済みの地図データから描画。1＝すすきの交差点、2＝つばさがある新ラーメン横丁。地図中心の既存座標を使用し、入口は示さない。点線は位置関係で、徒歩経路ではない。
- 旧実装はtransportation全件を道路化していた。brunnel=tunnelの地下鉄・地下通路とtransitを地表道路から除外。幅は従来同様にクラス別の概略値。歩道・横断歩道・実景看板はデータ未確認につき追加しない。
- 旧3D赤線は任意の制御点を結び建物を横切るため撤去。公式アクセスページとGoogle徒歩ルートへ案内する。
- カメラの注視点を街区内に制限。建物の平面ポリゴン（中庭を除く）にカメラが入る場合は屋上+5mへ退避。地表+4mを最低高にする。高さ不明の場合は既存の15m推定に基づくため実景の衝突保証ではない。
- 四角い装飾窓と陰影による網点。網点周期はDPRに合わせた4 CSS px。トーン用の環境光を1.5→0.65にし、明暗の差が点の密度として見えるようにした。
- 48pxの拡大縮小ボタン、カメラの選択表示、スマホで重複する案内パネルの整理。WebGL context lossでもエラーと再読み込みを表示する。
- 利用時は同一サイトの静的データのみ。AI API・Ollama・有料地図APIは使用しない。

## ローカル検証

`npm run test`（既存SEO、AI FAQ、公開契約）、`npm run build:location`、ローカルサーバーを起動して `node tests/location-browser-qa.mjs`。
`LOCATION_QA_EXECUTABLE` はMacに既にあるテストブラウザ実行ファイルを指定するための任意設定。CIの既存ブラウザ設定は変更しない。
3D QAにはカメラの見切れ・建物内侵入・二本指入力・PNG寸法/出典欄・GLBメタデータ・読み込み失敗/復旧・WebGL描画中断を追加。
